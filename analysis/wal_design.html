How the write-ahead log works

Three agents work on the same AppWorld task in one shared world, and can't message each other. The write-ahead log is their shared record: each agent posts what it intends to change, and the harness logs every change. Levels L1 to L4 decide how much of that is enforced.

Where reads, writes and log calls go

The checks on posting and on writing

Posting an intent and making a change pass the same three checks, in the same order. Each level turns some of them on.

The life of a claim

The levels

LevelWhat is enforced
L0No log. The agents share only the world.
L1The log exists and agents are asked to read it and post intents, but nothing is checked.
L2A write needs a claim in the agent's current intent: same app and API, and the record's id.
L3L2, and the agent must have read every entry before posting or writing.
L4L2, catching up only on entries about the same records (the rest are delivered without blocking), and conflicts with a teammate refused.
L4-strictL4 with L3's full catch-up, as a comparison.
