Hard tasks: where a single agent breaks, and why

Most WorkBench tasks need one change. We reran four systems on tasks whose correct answer makes 3 or more changes, and on tasks that need 5 or more, to see whether teams of agents help when there is real work to divide.

Every system falls with task size

The single agent goes from 60% on small tasks to 25% on 3+ and 0% on 5+ change tasks. The best team, decentralized, goes 80% → 42% → 17%.

The main cause is a search cap

WorkBench’s search tools return at most 5 records. In the published runs of 24 models, 47% of attempts at 5+ tasks stopped after exactly 5 of the main action.

Teams get past the cap by accident

On 5+ tasks the single agent never made more than 5 of the main action; agent-driven teams did in 7 and 9 of 12 tasks, as later searches found what earlier ones missed.

Getting past it isn’t enough

Teams still finished few 5+ tasks: wrong records (all of Lena’s customers instead of her leads), extras and duplicates sank the rest.

Accuracy by task size

Small: our 10-task sample (0–2 changes). 3+: 12 tasks sampled from the 64 needing 3 or more changes. 5+: 12 tasks sampled from the 27 needing 5 or more (6–12 each). One run per system per set.

How the teams handled big tasks

Agent-driven teams share one workspace, so a later search runs after a teammate’s deletions and returns the records that were cut off before.

“Got past the cap”: tasks where the system made more than 5 of the main action (deletions, updates), out of the tasks that needed more than 5. Agents making changes and the busiest agent’s share are averages per task.

What this means for the communication question

  1. Teams look better on big tasks partly because of one tool quirk.The cap punishes an agent that trusts its first search. Several agents in one workspace search again by accident. A fair comparison needs a single-agent baseline told to re-search until a query returns fewer than 5 results, or a search tool with a higher limit.
  2. On big tasks, communication changes character.Messages start carrying lists of IDs and requests to act on them, and work spreads across agents (2.0–2.2 agents making changes on 5+ tasks against 1.3–1.4 on small ones). That is the setting where agent-driven communication can earn its cost.
  3. Remaining failures are reading errors, not coordination errors.“Leads” read as all customers, “at any time” read as “always”, guessed addresses. More agents don’t fix a misreading they all share.
