How much enforcement does a shared log need?

The write-ahead log

Three agents get the same AppWorld task and work on the same apps and accounts. They cannot message each other. From level 1 on, they share a write-ahead log: an append-only record of what each agent intends to change and of every change made.

  • Reads go straight to the apps. Writes (any API call that changes something, apart from logging in and out) pass through the log service, which checks the level's rules, records the pending line, runs the write and records the change under one lock. A refused write raises an error in the agent's code that says why, and nothing changes.
  • Agents' code runs one cell at a time; their model calls run in parallel. Agents can only append intents; the harness writes every other entry, and no entry is ever edited.
  • The first complete_task call finishes the task for the team. It is logged, and no rule applies to it.

Five levels of enforcement

Each level keeps what the previous one enforces and adds one rule, except level 4, which changes how catching up works. L4-strict is run alongside as a comparison.

Catching up means reading every log entry the agent hasn't seen. A refusal for unread entries shows the agent what it missed, then it may retry. At L4, only unread entries about the same records (or, for new items, the same API) block a post or write; the rest are shown with the result. A conflict is a record a teammate has claimed or already changed, or a new item a teammate has claimed or already created.

Results by level

Conflicts between agents

A conflict is a write to a record, or of a new item, that a teammate had already written. It either went through a second time (a duplicate) or failed because the work was already done (a collision, such as "already downloaded").

Accuracy

A task-run counts as solved only if every one of AppWorld's tests passes: the expected changes, nothing else changed, and the right answer for questions.

Time, tokens and concurrency

All levels ran side by side in the same jobs, so their times saw the same load. Time is the team's wall time per task.

Overlap: share of the team's time with two or more agents working. Parallelism: the agents' summed working time over the team's time (1 means one agent at a time, 3 means all three throughout).

How agents used the log

Per task-run. Refusals are counted by the rule that fired; a refusal chain is a run of refusals with no accepted post or write in between.

Level against level, task by task

Each task-run is compared with the same task in the same job at the other level. p is a two-sided sign-flip test; the time interval is a 95% bootstrap interval.
