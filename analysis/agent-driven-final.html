What agents say when nobody schedules the conversation

The scaling paper’s multi-agent setups talk on a fixed schedule: every round, every worker writes a summary and the harness delivers it. We replaced that with an agent-driven team: three peers in one shared workspace who decide for themselves whether to talk, when, and through which channel: free-text messages, an A2A-style task protocol, or a shared state they create and edit.

Left alone, they don’t talk

With every channel open and WorkBench’s usual prompt, agents communicated in 2 of 10 tasks and never before acting. Each just did the job, and two or three agents changed the same thing in half the tasks.

Given a choice, prose and ad-hoc state

Asked to coordinate with every channel open, they used free-text messages and invented shared-state keys, and never opened an A2A task.

Structure carried data, not agreement

Every A2A and shared-state write was structured, yet claims still collided and each agent invented its own keys, so nobody read the others’ flags.

A fraction of the chatter

60–650 characters per task against 12,000–20,000 in the fixed-round setups, with no accuracy loss. None of the conditions beat the single agent on these small tasks.

Two ways to run the same team

Same model, same 27 WorkBench tools, same three agents. What changes is who decides about communication, and what the agents act on.

The paper’s rounds (mas.py)

  • The harness runs synchronized rounds; every worker acts, then writes a summary.
  • Summaries are delivered whether or not anyone needs them: to the orchestrator, to peers, or both.
  • Each worker has a private copy of the databases; an aggregation step (union, vote, orchestrator’s pick) decides the answer.
  • Agents can’t choose whom to contact, when, or in what format.

Agent-driven (agent_driven.py)

  • Three peers start at once and run independently; no rounds, no orchestrator.
  • One shared workspace: a change made twice happens twice, and the team is scored on the end state.
  • Optional channels: send_message; an A2A-style task protocol with states and JSON data; a shared key-value store, empty at the start, versioned, with change notifications.
  • Messages reach a busy agent between its turns and wake an idle one; the run ends when everyone is idle.

Conditions: all channels (free choice) or one channel at a time, and optionally one extra sentence: “Before you change anything in the workspace, agree with your teammates on who does what, so that no change is made twice.” It asks for coordination without saying how. Channel descriptions are listed in a different random order for each agent.

Patterns in the traces

Claims without arbitration

Agents announce “I’ll do it, nobody else touch it” at nearly the same moment, often after a teammate already did it.

Structure isn’t correctness

A2A payloads were clean JSON, but they carried guessed values, and two agents sometimes delegated the same question to each other.

A2A T1 agent_1 → agent_2{"email_id": "00000120", "recipient": "nadia@atlas.com"}T2 agent_1 → failedUnable to query all tasks due to API constraint; cannot determine person with fewest tasks.

Logging instead of locking

With channels open but no nudge, one task’s agents used shared state as a log of their duplicates: three agents each added the same lead.

last_added_lead_id v1, agent_200000200v2, agent_300000201v3, agent_100000202

They act before they read

Reads of shared state or task lists per task: 0.2 with all channels open, 0.5 with the nudge, 3.5 when shared state was the only channel. Versioning refused 2 stale writes, so the lock primitive was there; agents just didn’t use it to claim work.

Talk is cheap here

The one text-only condition with 90% of tasks coordinated spent 652 characters per task, about 3% of what decentralized rounds send, and matched the single agent’s 60%.

What this suggests

  1. The paper’s rounds overstate how much agents talk and hide the real coordination problem.Private workspaces plus a merge step mean duplicate work is filtered by the harness. In a shared workspace, duplicates are the main failure, and agents rarely prevent them unprompted.
  2. Free choice favors prose and ad-hoc shared state.When A2A was optional it appeared in one task out of twenty. When it was the only channel, they used it for delegation and status, with structured data, but structure didn’t fix wrong values or colliding claims.
  3. The missing piece is agreement, not format.A claim primitive with arbitration (first writer wins, others see it before acting), a shared key convention, and a read-before-write habit would address the failures we saw better than a richer message schema.
  4. Test where teamwork has room.Tasks needing 3+ changes, composite requests that chain several independent tasks, and teams where each agent holds only some tools (one per domain, as in AppWorld) so information has to be exchanged.
